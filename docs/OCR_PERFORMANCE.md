# Ускорение поиска текста — 15 октября 2026

Локальное изменение после версии 1.0.10, пока не выпущено.

## Изменения

- Окно поиска использует ограниченный конвейер: максимум два изображения одновременно, каждый обработчик имеет свой запрос Apple Vision. Следующий файл запускается по завершении одного из текущих, задачи на весь набор сразу не создаются.
- Поддерживаемые языки и ревизия определяются один раз на поиск. При попадании в кэш не создаётся запрос распознавания для каждого изображения.
- Прогресс отправляется в UI не чаще одного раза за 100 мс, плюс начало и окончание. Это уменьшает очередь обновлений при быстром чтении кэша.
- Порядок результатов и предупреждений сохраняется независимо от порядка завершения обработчиков. Файлы перепроверяются до/после распознавания и перед выдачей итогового отчёта; отмена не возвращает неполный отчёт как готовый. Существующий идентификатор поколения в UI отбрасывает поздние результаты старого поиска.

Точность `.accurate`, коррекция языка, поддерживаемые RU/EN, автоматическое определение языка, поворот EXIF, ограничение 3 000 px и порог confidence 0,4 не менялись. Сигнатура и формат дискового кэша сохранены. Облачных API нет.

## Измерения

macOS 26.6.2, arm64, оптимизированная компиляция. Только синтетические PNG/JPEG с RU/EN текстом, короткой вывеской, пустым изображением и пейзажем. Набор из 500 файлов состоит из повторов этих примеров под разными путями; типичные текстовые картинки — 1 400 × 900. Перед каждым холодным замером использован отдельный пустой кэш. Под «холодным» здесь понимается отсутствие OCR-кэша, а не сброс файлового кэша ОС или состояния Vision.

| Сценарий | Ранее | После |
| --- | ---: | ---: |
| 33 изображения, без OCR-кэша | 2,675 с | 2,224 с |
| 500 изображений, без OCR-кэша | 35,558 с | 30,574 с |
| 500 изображений, повтор из кэша | 0,092 с | 0,054 с |
| Пиковый RSS CLI-процесса, 500 изображений | 256,9 МиБ | 265,4 МиБ |

Первый поиск на 500 файлах занял примерно на 14% меньше времени. Отдельный замер нового конвейера с одним обработчиком на 33 файлах — 2,595 с. Новый конвейер также прочитал все 500 записей старого кэша без повторного OCR (0,069 с). Распознанные строки всех 33 и всех 500 изображений сравнены автоматически и полностью совпали с исходной версией.

Это отдельные последовательные прогоны, не статистическая оценка и не гарантия той же скорости на любой машине. Пиковая память относится к CLI-процессу, а не ко всему GUI/системным службам Vision. M2/8 ГБ отдельно как конфигурация измерения не подтверждался; большие HEIC/RAW, мелкий текст и pressure/swap не измерялись. Набор из повторов синтетических примеров не заменяет разнообразную фотоколлекцию.

## Проверки

- Полный `--self-test` EN/RU прошёл после изменений из отдельного снимка исходников. Новые проверки сравнивают последовательный и параллельный OCR: текст, порядок, предупреждение о повреждённом изображении, пропущенные файлы, кэш, режим одного обработчика и пустой набор.
- Проверены изменение файлов во время работы и отмена после начала обработки: изменённые файлы исключены, частичный отчёт отменённого поиска не выдаётся как завершённый.
- В изолированной тестовой `.app` с собственным bundle ID/историей, при отключённом кэше, проверены остановка и повторный запуск на 500 картинках, прогресс, успешное завершение (364 результата с текстом из 500) и поиск «Привет» (122 результата). Прогресс и результат просмотрены на снимках окна. Пользовательский OCR-кэш не очищался и не использовался; файловые действия в UI не выполнялись. Матрица размеров/тем/языков UI не прогонялась.
- Исходники и результаты замеров: `/private/tmp/grape-ocr-speed.5XIF2h`; снимок для окончательной компиляции — `verified`, отдельная тестовая `.app` — `Grape OCR Test.app`.

При остановке текущий синхронный вызов Vision может ещё завершаться; новые файлы отменённой задачи не должны попадать в итоговый отчёт. Мгновенное прекращение всех системных вычислений не обещается.

Для повторных поисков полезно оставлять включённым «Кэшировать текст локально». Изменение фразы, порогов и фильтра уже работает по готовому тексту без повторного OCR. Первый проход по новым изображениям всё ещё требует распознавания каждого файла; многократное ускорение за счёт снижения качества здесь не вводилось.
