# Безопасность файлов, состояния и фоновых задач

## Переименование

Операция выполняется в исходной папке. Сейчас движок использует промежуточные имена, эксклюзивное renameatx_np с RENAME_EXCL, проверку FileStamp и откат. Сохраняй защиту от конфликтов, включая обмен имён, регистр и Unicode. Не заменяй этот механизм на copy/delete или rename с перезаписью ради обхода ошибки.

Перед операцией проверяются исходники, допустимость имён, уникальность назначений и существующие назначения. Точные поля времени в FileStamp — секунды и наносекунды; не пересохраняй округлённый mtime после переименования. Не меняй расширение как побочный эффект шаблона.

При ошибке откат должен учитывать фактическое местоположение каждого файла. Сообщение «Исходные имена восстановлены» допустимо только при успешном полном откате. Если откат неполный, покажи оставшиеся пути и причину. Журнал должен позволять восстановление после прерывания приложения между этапами.

Не обещай одинаковую поддержку всех томов. APFS, HFS+, exFAT/FAT, NTFS с драйвером и сетевые ресурсы могут отличаться правами, точностью времени и поддержкой системных вызовов. Для нового fallback нужны отдельный дизайн без перезаписи, тесты на нужной ФС и проверка отката. Ошибка Operation not supported сама по себе не повод ослаблять гарантии.

## Импорт и идентичность

Не следуй символическим ссылкам рекурсивно. Не выходи за выбранные пользователем корни из-за ссылок. Скрытые файлы и пакеты обрабатывай согласно существующим правилам; обычный импорт и рекурсивный поиск — разные сценарии. Повторные пути исключаются, одинаковые inode учитываются с device ID. Не сравнивай inode с разных дисков как один файл.

Перемонтированный диск, исчезнувший файл и изменение содержимого после сканирования требуют перепроверки. Наличие доступа на чтение не означает доступа на переименование или Корзину. Не копируй всё на системный диск только ради анализа.

## Удаление и экспорт

- Снимок набора для подтверждения фиксируется заранее. Число в диалоге соответствует именно этому набору, а не вычисляется заново из меняющегося фильтра после нажатия.
- Перед любым действием перепроверь весь выбранный набор; затем каждый файл непосредственно перед действием. Если предварительная проверка не прошла, не начинай пачку.
- Не делай безвозвратный fallback, если trashItem не поддерживается, диск read-only или отсутствует право доступа. Покажи ошибку, оставь файл в результатах.
- В дубликатах фильтрация защищённого файла обязательна на уровне получения файлов для действия. Даже ошибочный checkbox не должен удалить keeper.
- В OCR все найденные файлы могут быть единственными оригиналами. Подтверждение явно отличается от удаления дубликатов.
- Экспорт не перезаписывает совпадающее имя назначения. Не удаляй назначение ради успешного copy/move. Исходная папка не является допустимым способом переименовать экспортом тот же файл.
- После частичного успеха удаляй из результатов и основного списка только действительно перемещённые/отправленные в Корзину файлы. Покажи число успешных действий и отдельные ошибки. Скопированные исходники остаются в списках.
- История переименования не считается отменой OCR-перемещения или удаления. Восстановление из Корзины выполняется Finder.

## Поиск дубликатов и похожих фото

Для точных дубликатов: сначала размер, затем SHA-256 порциями, затем сравнение байтов. Не считай совпадение размера доказательством и не загружай большие файлы полностью в память. Проверяй FileStamp до/после чтения. Отмена не публикует неполный отчёт как завершённый.

Похожие фотографии — рекомендация для ручного просмотра, не точные копии. Не применяй к ним автоматическое удаление всех похожих без отдельного продуктового решения. Порог Vision не обозначает процент сходства; изменение ревизии Vision/порога/хеша требует повторных проверок на похожих и отличающихся изображениях.

## OCR и кэш

Распознавание выполняется Apple Vision локально. Языки определяются из действительно поддерживаемых системой. Учитывай EXIF-ориентацию при декодировании; ограничивай размер декодируемой картинки. Если анализируется только первая страница/кадр, сохраняй явное описание ограничения.

«Текст не обнаружен» означает успешное распознавание без надёжных строк, а не ошибку чтения. Не выдавай OCR за безошибочный классификатор скриншотов. Поиск по фразе и пороги количества текста должны менять фильтрацию без запуска полного OCR заново.

Кэш включает распознанный текст, хранится локально и отключается пользователем; есть очистка. Валидность зависит от полного FileStamp, ревизии алгоритма и настроек распознавания. При изменении настроек обнови сигнатуру кэша. Не помещай пользовательский OCR-текст в репозиторий, логи, issue или релиз. Кэш — расходные данные; ошибка его чтения/записи не должна ломать сканирование. Не удаляй файлы за пределами собственной директории кэша.

## Фоновые задачи и сохранение

Чтение/вычисления — вне главного потока. Между задачами передавай Sendable-значения; опубликованное состояние — MainActor. Для результатов/прогресса используй идентификатор поколения, чтобы отменённый старый поиск не заменил новый. Проверяй отмену между файлами и порциями длительного чтения; освобождай декодированные изображения и handles по мере обработки.

История/шаблоны/журнал записываются атомарно, с версией формата и совместимостью с существующими данными. Ошибка сохранения не маскируется успешным UI. Неподтверждённая возможность сохранить/отменить операцию не должна превращаться в обещание надёжной истории. Не сбрасывай пользовательскую историю ради прохождения теста.
