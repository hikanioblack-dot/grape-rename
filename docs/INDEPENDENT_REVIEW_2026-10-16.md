# Независимая регрессия локальной UI-сборки

Проверка чата «Тестирование и ошибки», 16 октября 2026. Swift-код не изменялся, релиз не выпускался.

Проверена `Review/2026-10-15-UI/Grape Rename UI Test.app`, база 1.0.10/build 10. SHA-256 исходного бинарника: `855f51f7d624867442275785c049ef326a86d990c22ff29cef4103749855f138` — совпал с build-info.json. Исходники Source Snapshot и соответствующие Swift-файлы checkout совпали с source-hashes.json.

## Найденные проблемы

### P1 — импорт папки блокирует главный поток при задержке файлового провайдера

Временная копия приложения с собственными bundle ID/историей и английскими строками не открыла доступное для управления окно, когда GrapeTestFiles указывал на новую синтетическую папку `Review/2026-10-15-UI/Verification/Independent-2026-10-16/02 Duplicates and Similar` внутри Documents/iCloud. UI-инструмент дважды вернул timeout.

Два независимых `sample` одного процесса с интервалом около 27 секунд показывают весь главный поток на одной цепочке:

`ContentView.onAppear → Model.load → FileImport.collect → contentsOfDirectory → open`.

Это подтверждённая блокировка UI синхронным чтением, а не только предположение по тайм-ауту. После сохранения стеков завершён только временный тестовый процесс. Синтетические файлы скопированы в `/private/tmp`, в той же временной app изменён только тестовый путь; следующий запуск открыл окно и позволил завершить проверки.

Код: Model.swift:130–144 и FileImport.swift:6–23 в проверенном снимке. Риск уже отмечался общим аудитом, теперь получено воспроизведение на текущей сборке. Причина задержки самого `open` не установлена: участие File Provider вероятно по расположению папки и атрибутам, но не доказано отдельно. Нет оснований утверждать, что новые меню вызвали эту проблему или что она возникает на любой локальной папке.

Следующий шаг: отдельная правка фонового импорта, с защитой от устаревших результатов и конфликтующих действий; проверить на локальной и синхронизируемой папках. В этой проверке не исправлялось.

### P2 — текущая тестовая app в синхронизируемой папке не проходит строгую проверку подписи

`codesign --verify --deep --strict` текущего подготовленного bundle завершился с exit 1: `resource fork, Finder information, or similar detritus not allowed`. На корне `.app` обнаружен `com.apple.FinderInfo`; также есть File Provider/provenance-атрибуты. Бинарник при этом совпал с зафиксированным хешем, self-tests прошли.

Исходная тестовая app не очищалась и не переподписывалась. Только новая временная копия в `/private/tmp` очищена от собственных xattrs и подписана ad-hoc после изменения тестового Info.plist; её строгая проверка прошла.

Это замечание к текущему тестовому артефакту и месту хранения, не доказательство нарушения подписи публичного DMG 1.0.10. Перед передачей установщика нужна чистая упаковка и проверка приложения внутри DMG по TESTING_AND_RELEASES.md.

### P3 — английское подтверждение для одного выбранного файла использует множественное число

Воспроизведение: OCR → With Text → отметить Small sign.png → Move Selected to Trash… (1). Заголовок: `Move 1 selected files to Trash?`. Количество и область верны, действие отменено. Нужно отдельное согласование единственного/множественного числа в `ImageTextActionSnapshot.confirmationTitle` (TextSearchView.swift:13). Это текстовый дефект, а не нарушение набора удаления.

Созданы новые копии в `Verification/Independent-2026-10-16`; существовавшая `Verification/OCR Trash` не использовалась. Пользовательские Originals/Working не менялись.

2. Отмечен checkbox **Small sign.png**, затем открыт предпросмотр **Document photo.jpg**. Выбор остался равен 1: предпросмотр не заменяет отметку.
3. Подтверждение показало «Выбранные файлы в Корзину: 1?», фильтр «С текстом» и отсутствие защищённой копии. После отмены все проверочные файлы совпали с исходным снимком по SHA-256.
4. Повторно подтверждено действие. UI сообщил об одном файле в Корзине, выдача стала 4/6. На диске отсутствовал только **Small sign.png**, остальные проверочные файлы сохранили байты и mtime. Корзина не очищалась.
5. Отмечен Chat screenshot.png, затем введено `GRAPE2048`. Выдача сузилась до Document photo.jpg, выбор стал пустым, основная кнопка отключена. Копирование/перемещение в меню также отключены. Скрытая отметка в действие не попала.
6. «Действия → Все результаты фильтра в Корзину… (1)» открыло отдельное подтверждение для одного результата и фразы `GRAPE2048`. Действие отменено.
7. Отмечен только Document photo.jpg и скопирован в новую папку Export. Исходник остался. Повторное копирование в ту же папку показало ошибку совпадающего имени; копия и исходник не перезаписаны.
8. Тот же отмеченный документ перемещён в новую папку Moved. В назначении совпали байты, исходник исчез, текущая выдача по фразе стала пустой, отметки сброшены. Другие файлы остались.
9. В английской временной app полный набор снова дал 5/7; checkbox Small sign.png дал количество 1, проверено английское предупреждение и отмена. Новых удалений в этой копии не было.

Снимки подтверждений и существенных окон просмотрены и показаны в этом чате. Отдельные PNG в папку проверки не экспортировались.
